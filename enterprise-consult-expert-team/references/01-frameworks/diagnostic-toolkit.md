# 诊断工具箱：假设驱动的结构化问题分析

> 适用成员：全员。Phase 1 体检与 Phase 3 联合会诊的核心方法论。

## 一、假设驱动法（Hypothesis-Driven）

咨询的标准打法：**先提假设，再找证据**，而不是漫无目的地收集数据。

```
症状 → 提出 2-3 个根因假设 → 为每个假设设计验证问题
     → 收集证据 → 证实/证伪 → 收敛到主根因
```

**规则：**
1. 假设必须可证伪（"执行力差"不可证伪；"审批层级超过 4 级导致决策周期 >2 周"可证伪）
2. 每个假设标注置信度（高/中/低），低置信度假设必须附验证路径
3. 证据优先级：企业内部数据 > 访谈事实 > 行业基准 > 经验推断（经验推断必须标注为假设）

## 二、议题树（Issue Tree）

把"企业怎么了"拆成互不重叠、完全穷尽的子问题（MECE）。

**拆分维度示例（增长停滞）：**
```
增长停滞
├── 收入端
│   ├── 新客获取（流量×转化率×客单价）
│   └── 老客经营（留存率×复购频次×客单价）
└── 利润端
    ├── 毛利（定价×成本结构）
    └── 费用（销售/管理/研发费用率）
```

**规则：** 拆到"每个叶子节点都能用一个指标衡量"为止。拆不出指标的节点 = 拆错了。

## 三、5Why 根因下钻（升级版）

连续追问"为什么"，直到**管理层可行动层级**。

**可行动判定标准：**
| 层级 | 示例 | 是否可行动 |
|------|------|-----------|
| 症状 | 销售额下滑 20% | ❌ 这是症状 |
| 直接原因 | 大客户流失 3 家 | ❌ 还是表象 |
| 系统原因 | 交付延期导致客户流失 | ⚠️ 接近了 |
| 根因 | 排产依赖厂长个人经验，无计划系统 | ✅ 可行动（上排产系统/建计划岗） |
| 不可行动 | "员工不努力""市场不景气" | ❌ 死胡同，重新下钻 |

**鱼骨图辅助**（人机料法环测）：当 5Why 分叉时，用鱼骨图展开候选原因，逐条验证排除。

## 四、对标分析（Benchmarking）

1. **内部对标**：与自身历史最好水平比（趋势恶化点）
2. **同业对标**：与行业中位数/标杆企业比（结构差距点）——基准见 `02-benchmarks/`
3. **跨行对标**：流程问题可参考其他行业的成熟解法（如餐饮翻台率思维用于服务业产能）

**规则：** 对标必须注明基准来源与统计口径，口径不一致的对标 = 误导。

## 五、常见诊断谬误（自查清单）

| 谬误 | 表现 | 纠正 |
|------|------|------|
| 幸存者偏差 | 只研究成功企业做法 | 同时看失败案例 |
| 归因于单一因素 | "都是销售不行" | 用议题树穷举 |
| 相关当因果 | 上系统后业绩涨 = 系统有用 | 找对照期/排除同期变量 |
| 沉没成本 | "投了这么多不能停" | 只看未来现金流 |
| 把症状当根因 | 开"提升销售额"的处方 | 必须下钻到可行动层级 |
