# 数字化转型打法库

> 主要适用：陆云桥（数字化）。Phase 1 体检与 Phase 4 处方时使用。

## 一、数字化成熟度四级模型

| 级别 | 特征 | 典型状态 | 该级别的禁忌 |
|------|------|---------|-------------|
| L1 单点工具 | Excel + 微信 + 零散软件，数据在人脑和表格里 | 多数小微企业 | 禁止直接上中台/AI |
| L2 局部集成 | 核心业务有系统（ERP/CRM），但系统间不通 | 成长型企业常见 | 禁止推倒重来换全套 |
| L3 数据驱动 | 数据打通，有报表体系，决策看数据 | 中型企业目标态 | 禁止为建而建的数据中台 |
| L4 智能决策 | 预测式分析、AI 辅助决策、自动化执行 | 少数领先企业 | — |

**定级铁律**：处方只允许比当前级别高一级。L1 企业的处方 = 先把核心流程线上化（到 L2），而不是上 AI。

## 二、转型路线图模板

```
第 1 步（0-3 月）：选一个最疼的业务环节做数字化试点（快速见效，建立信心）
第 2 步（3-9 月）：核心系统补齐或替换，打通试点与其他环节的数据
第 3 步（9-18 月）：数据资产化——统一口径、报表体系、经营驾驶舱
第 4 步（18 月+）：数据驱动决策 → 选择性引入 AI/自动化
```

**试点选择标准**：疼（业务抱怨多）+ 小（3 个月内能上线）+ 可衡量（有前后对比指标）。

## 三、系统选型决策框架

| 维度 | 问题 | 权重 |
|------|------|------|
| 业务匹配 | 覆盖核心流程的 80% 吗？剩下 20% 能配置吗？ | 高 |
| 总成本 TCO | license + 实施 + 运维 + 组织适应成本，3 年总计 | 高 |
| 数据主权 | 数据能导出吗？供应商锁定风险？ | 高 |
| 集成能力 | 有开放 API 吗？能和现有系统打通吗？ | 中 |
| 供应商存续 | 这家厂商 5 年后还在吗？ | 中 |

**红线**：不选"功能最全"的，选"最匹配当前成熟度"的。功能超出组织消化能力 = 烂尾。

## 四、常见失败模式（处方预审时对照）

| 失败模式 | 表现 | 预防 |
|----------|------|------|
| 领导工程 | 老板拍脑袋上系统，业务不认 | 试点先赢小仗 |
| 大跃进 | L1 直接上 L4 方案 | 按成熟度逐级走 |
| 数据垃圾场 | 系统上了但没人维护数据，报表不可信 | 先定数据责任人和录入标准 |
| 换系统不换脑子 | 旧流程原样搬进新系统 | 上线前先简化流程（联动运营科） |
| 重建设轻运营 | 上线即巅峰，三个月后没人用 | 处方必须含运营机制与使用率指标 |

## 五、AI 改造机会评估（新）

评估"这个环节能不能用 AI"的四问：
1. **有数据吗**：该环节有结构化数据或文档积累吗？没有 → 先补数据基建
2. **有容错吗**：AI 出错的代价可接受吗？高代价环节（合同审查、财务付款）= 人机协同，不全自动
3. **高频吗**：低频环节做 AI 不划算
4. **算得过账吗**：节省的人力成本 > 工具成本 + 试错成本？

**优先级排序**：营销内容生产 > 客服知识库 > 文档处理 > 数据分析辅助 > 决策辅助（由易到难）。
